Getting started

All API requests use the branded production base URL:

https://wap.mobiwave.co.ke/api/v1

Keep API keys in a server-side secret manager. Never expose them in browser code or a public repository.

Authentication

Create an integration key under Workspace → Integrations → Developer API. Each key has a Client ID, integration name and explicit permissions. The secret is displayed once.

Authorization: Bearer mw_live_YOUR_SECRET

You may alternatively use X-API-Key. The Client ID is an identifier, not a credential. Every request is tenant-scoped to the workspace that owns the key.

Scopes

messages:send · messages:read · contacts:read · contacts:write · templates:read · campaigns:read · campaigns:write

Send messages

POST /messages — unified send endpoint. Supported types: template, text, image, document, audio and video.

Include Idempotency-Key on every send. Reuse the same key and same body after an uncertain outcome.

Template

{
  "to": "+254712345678",
  "type": "template",
  "template": {
    "name": "order_update",
    "language": "en",
    "parameters": ["Jane", "MW-1042"]
  }
}

Text (inside Meta's 24-hour customer-service window)

{
  "to": "+254712345678",
  "type": "text",
  "text": { "body": "Your order has been dispatched." }
}

Image or document

{
  "to": "+254712345678",
  "type": "image",
  "image": {
    "link": "https://cdn.example.com/product.jpg",
    "caption": "Your product is ready."
  }
}

Document, audio and video use their respective object with a publicly accessible HTTPS link. Meta validates media formats, sizes and availability.

Recipients must exist in the workspace and have recorded opt-in consent. Text and media are subject to the 24-hour customer-service window. Templates must be Meta-approved.

Accepted response

{
  "ok": true,
  "data": {
    "message_id": "wamid.example",
    "status": "accepted",
    "type": "template",
    "to": "+254712345678"
  },
  "meta": {
    "idempotent_replay": false,
    "persistence_warning": false
  }
}

Accepted means Meta accepted the submission, not that the recipient received it.

Legacy compatibility

POST /messages/send remains available for existing template-only integrations using template_name, language_code and components.

Create or upsert a contact

{
  "phone": "+254712345678",
  "name": "Jane Doe",
  "consent_status": "opted_in",
  "consent_source": "Website checkout checkbox",
  "metadata": { "customer_ref": "C-1042" }
}

Record consent change

{
  "status": "opted_out",
  "source": "Customer request via support"
}

Consent changes are audited with previous and new status, source, timestamp and API key. A source is required. Deleting a contact also deletes its linked records.

Templates

GET /templates and GET /templates/{id} require templates:read. Templates are synchronised from the connected Meta WhatsApp Business Account. Only approved templates can be sent.

Message history

GET /messages and GET /messages/{meta_message_id} require messages:read. Lists are newest first.

Create a campaign

{
  "name": "November order updates",
  "template_id": "00000000-0000-4000-8000-000000000000",
  "contact_ids": [
    "00000000-0000-4000-8000-000000000001",
    "00000000-0000-4000-8000-000000000002"
  ],
  "scheduled_at": "2026-12-01T08:00:00+03:00"
}

scheduled_at is optional and must be in the future. Campaigns use approved templates and explicit contact IDs. Every recipient must belong to the same workspace and be opted in. Existing batch limits, quota controls and uncertain-outcome protections remain active.

Customer webhooks

Configure customer webhooks under Integrations → Customer webhooks. This is separate from Meta's inbound callback. Current events: message.inbound, message.status, message.outbound, campaign.completed.

Verify X-MobiWave-Signature as sha256=<hex> HMAC-SHA256 over the exact raw JSON body. Deduplicate using X-MobiWave-Delivery. Failed deliveries are retried with backoff.

Errors and limits

Structured errors use this format:

{
  "ok": false,
  "error": {
    "code": "INVALID_RECIPIENT",
    "message": "to must be an E.164 phone number.",
    "details": null
  }
}
StatusMeaning
400Invalid request
401Invalid API key
403Missing scope, feature or consent
404Resource not found
409Conflict or idempotency issue
413Body exceeds 128 KiB
422Validation failure
429120 requests/minute per key or usage limit
500–504Server or provider error

List endpoints accept limit (1–100, default 50) and offset (default 0).

Code examples

Store the key in MOBIWAVE_API_KEY.

cURL

curl https://wap.mobiwave.co.ke/api/v1/messages \
  -X POST \
  -H "Authorization: Bearer $MOBIWAVE_API_KEY" \
  -H "Idempotency-Key: order-1042-message-v1" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "+254712345678",
    "type": "template",
    "template": {
      "name": "order_update",
      "language": "en",
      "parameters": ["Jane", "MW-1042"]
    }
  }'

JavaScript (Node.js 18+)

const response = await fetch("https://wap.mobiwave.co.ke/api/v1/messages", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.MOBIWAVE_API_KEY}`,
    "Idempotency-Key": "order-1042-message-v1",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    to: "+254712345678",
    type: "template",
    template: { name: "order_update", language: "en", parameters: ["Jane", "MW-1042"] }
  })
});
const result = await response.json();
if (!response.ok) throw new Error(result.error?.message ?? `API error: ${response.status}`);
console.log(result.data);

Python

import os, requests

response = requests.post(
    "https://wap.mobiwave.co.ke/api/v1/messages",
    headers={
        "Authorization": f"Bearer {os.environ['MOBIWAVE_API_KEY']}",
        "Idempotency-Key": "order-1042-message-v1",
    },
    json={
        "to": "+254712345678",
        "type": "template",
        "template": {"name": "order_update", "language": "en", "parameters": ["Jane", "MW-1042"]},
    },
    timeout=30,
)
response.raise_for_status()
print(response.json()["data"])

PHP (cURL)

$payload = [
  "to" => "+254712345678",
  "type" => "template",
  "template" => ["name" => "order_update", "language" => "en", "parameters" => ["Jane", "MW-1042"]],
];
$ch = curl_init("https://wap.mobiwave.co.ke/api/v1/messages");
curl_setopt_array($ch, [
  CURLOPT_POST => true,
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_HTTPHEADER => [
    "Authorization: Bearer " . getenv("MOBIWAVE_API_KEY"),
    "Idempotency-Key: order-1042-message-v1",
    "Content-Type: application/json",
  ],
  CURLOPT_POSTFIELDS => json_encode($payload),
]);
$body = curl_exec($ch);
$status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
if ($body === false || $status < 200 || $status >= 300) throw new RuntimeException("MobiWave API request failed: " . curl_error($ch));
curl_close($ch);
echo $body;

Meta callback

Configure Meta's webhook callback URL as https://wap.mobiwave.co.ke/api/webhooks/whatsapp. Use the verification token from Integrations → Meta connection and subscribe to messages and message_template_status_update.

MobiWave uses the official Meta WhatsApp Cloud API. Meta policies, approved template requirements, customer-service windows, account limits and message charges continue to apply. Never call internal Supabase function URLs directly.
