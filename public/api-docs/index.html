Developer API

Send approved WhatsApp template messages from your server using a workspace-scoped MobiWave API key. The public API runs on the MobiWave WA domain; provider infrastructure remains internal.

Quick start

  1. In MobiWave WA, open Integrations → Developer API.
  2. Create a workspace API key. The full key is displayed once; copy it immediately and store it in your server-side secret manager.
  3. Ensure the recipient exists in the workspace contacts with recorded opt-in consent.
  4. Sync an approved WhatsApp template from Meta and use its exact name and language code.
  5. Send a request to the endpoint below.
Keep your key private. Never embed it in browser JavaScript, a mobile app, source control, or client-visible HTML. Revoke a key immediately if it is exposed.

Base URL and authentication

Base URL

https://wap.mobiwave.co.ke/api/v1

Send the API key in the X-API-Key header. Bearer authorization is also accepted.

X-API-Key: mw_live_YOUR_SECRET_KEY
Content-Type: application/json
Idempotency-Key: YOUR_UNIQUE_REQUEST_ID

Keys are scoped to one workspace and require the messages:send permission. Expired or revoked keys are rejected. The raw key is stored as a hash and cannot be retrieved after creation.

Send an approved template

POST https://wap.mobiwave.co.ke/api/v1/messages/send

{
  "to": "+2547XXXXXXXX",
  "template_name": "approved_template",
  "language_code": "en",
  "components": []
}

to must be an E.164 phone number. template_name and language_code must match a template synchronized from Meta and marked approved. For templates with variables, pass the required Meta template components and parameters.

Template with a body variable

{
  "to": "+254712345678",
  "template_name": "order_update",
  "language_code": "en",
  "components": [
    {
      "type": "body",
      "parameters": [
        { "type": "text", "text": "Jane" },
        { "type": "text", "text": "MW-1042" }
      ]
    }
  ]
}

The parameter order and types must match the approved template definition in Meta.

Code examples

cURL

curl --request POST \
  --url https://wap.mobiwave.co.ke/api/v1/messages/send \
  --header "X-API-Key: $MOBIWAVE_API_KEY" \
  --header "Idempotency-Key: order-MW-1042-update-v1" \
  --header "Content-Type: application/json" \
  --data '{
    "to": "+254712345678",
    "template_name": "order_update",
    "language_code": "en",
    "components": []
  }'

PHP (cURL)

<?php
$payload = [
  "to" => "+254712345678",
  "template_name" => "order_update",
  "language_code" => "en",
  "components" => [],
];

$ch = curl_init("https://wap.mobiwave.co.ke/api/v1/messages/send");
curl_setopt_array($ch, [
  CURLOPT_POST => true,
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_HTTPHEADER => [
    "X-API-Key: " . getenv("MOBIWAVE_API_KEY"),
    "Idempotency-Key: order-MW-1042-update-v1",
    "Content-Type: application/json",
  ],
  CURLOPT_POSTFIELDS => json_encode($payload),
]);
$body = curl_exec($ch);
$status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
if ($body === false || $status < 200 || $status >= 300) {
  throw new RuntimeException("MobiWave API request failed: " . curl_error($ch));
}
curl_close($ch);
echo $body;

Idempotency and retries

Every send requires an Idempotency-Key between 8 and 200 characters. Generate a stable unique value for each logical send (for example, an order ID plus message purpose). If the network times out or the result is uncertain, retry the exact same request with the same key and same body. Do not create a new key to retry an uncertain request: doing so could submit a second message.

Reusing a key with a different request body is rejected. A successful API response means Meta accepted the message for processing; it does not mean the recipient's device has received it. Delivery status is updated from Meta webhook events.

Responses

Successful submission returns JSON similar to:

{
  "ok": true,
  "message_id": "wamid...",
  "status": "accepted"
}

Always treat the HTTP status as authoritative and parse the response body. Store the returned message ID for support and reconciliation.

HTTP errors

StatusMeaning / action
400Invalid recipient, template name, JSON, or idempotency key. Correct the request.
401Missing, invalid, expired, revoked, or insufficiently scoped API key. Create or replace the key.
403API feature unavailable, recipient lacks recorded opt-in, or template is not approved. Check plan, consent, and template status.
409Official Meta Cloud API connection is not enabled for this workspace.
413Request body exceeds the 128 KiB API limit.
429Configured monthly workspace message limit reached.
502Meta rejected the request or the provider outcome needs reconciliation. Do not blindly send again with a new key.
503Plan access or usage state could not be verified. No message may have been submitted; follow the returned error guidance.
504Provider outcome is unknown. Reconcile and retry only with the same idempotency key and body.

Customer event webhooks

Workspace administrators can configure customer event destinations under Integrations → Advanced: customer event webhooks. These are separate from the Meta callback: customer webhooks send MobiWave events to your application. Destinations must use HTTPS, standard port 443, and a public DNS hostname.

Supported event subscriptions include message.inbound, message.status, message.outbound, conversation.updated, and campaign.completed. Each delivery body is JSON in this shape:

{
  "id": "delivery-uuid",
  "type": "message.status",
  "created_at": "2026-11-26T12:00:00.000Z",
  "data": {}
}

Headers include X-MobiWave-Event, X-MobiWave-Delivery, X-MobiWave-Signature, and Idempotency-Key. The signature is sha256= followed by the lowercase hex HMAC-SHA256 of the exact raw request body using the signing secret shown once when the webhook is created.

Verify a webhook signature (Node.js)

import crypto from "node:crypto";

function verifyMobiWaveWebhook(rawBody, signature, secret) {
  const expected = "sha256=" + crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");

  const received = Buffer.from(signature || "");
  const expectedBuffer = Buffer.from(expected);
  return received.length === expectedBuffer.length &&
    crypto.timingSafeEqual(received, expectedBuffer);
}

Deduplicate deliveries using X-MobiWave-Delivery or the body id; webhook handlers should return a 2xx response promptly after safely accepting the event. Failed deliveries are retried with backoff, up to the platform's retry limit.

Operational notes

  • Only official Meta WhatsApp Cloud API connectivity is supported.
  • Only approved template messages are supported by this public API; it is not an arbitrary message relay.
  • Recipients must exist in the same workspace and have recorded opt-in consent.
  • Message usage is metered per workspace.
  • Never share API keys or webhook signing secrets with frontend code or untrusted parties.
